## 二、产品定位与目标

### 2.1 一句话定位

知隙是一款面向不同学习者的知识检验助手：用户提供自己已经学习过的资料，知隙自动提取知识点并生成待办清单，结合重要程度和掌握情况主动提问、追问，通过资料和外部依据进行反馈，帮助用户了解哪些内容表达清楚、哪些地方仍需确认。

### 2.2 目标用户

面向有自我检验需求的人，不限定专业、行业或年龄，例如：

- 学生：检验自己对课程资料、复习笔记或知识点的理解。
- 自学者：根据书籍、笔记或其他资料进行回顾与自测。
- 求职者或职场人士：围绕准备过的内容进行口述练习和模拟面试。

以上只是例子，不作为限定用户群体或首版支持学科的承诺。

### 2.3 核心目标

1. 让用户以自己的学习资料为主要范围，检验是否能够理解和表达相关内容。
2. 以知隙主动发起问题和追问为主要交互方式，同时允许用户主动提问、指定重点和调整过程。
3. 给出能够回溯用户回答、资料原文和外部来源的判断依据。
4. 对证据不足、不同表达和开放性问题保持审慎，允许用户纠正判断。
5. 将知识点组织为待办清单，按重要程度和用户表现动态安排检验，清晰展示完成进度。
6. 为每个知识点设定追问上限和完成标准，避免持续循环；支持模拟面试，并为后续复查与复测保留记录。

**边界**：知隙以检验已有学习成果为主要用途。解释问题、说明判断依据和应用户请求进行讨论可以支持，但系统性讲课或替用户制定学习课程不是本轮确定的核心目标。

### 2.4 衡量价值的方向

建议通过真实使用和人工核对检验以下问题，而不预先声称产品已经达到某种学习效果：

- 问题是否围绕用户选择的资料和目标。
- 追问能否帮助澄清用户的回答。
- 评价是否准确反映用户所说的内容，并能提供可复查的依据。
- 用户能否区分资料内的内容、外部核验信息和尚待确认的问题。
- 用户能否依据记录再次检验之前不明确的知识点。

## 三、已确认方向与工作假设

### 3.1 已确认

| 编号 | 方向 |
| --- | --- |
| C01 | 项目重新开始开发，不再以迁移旧项目为目标。 |
| C02 | 产品面向不同学习者，不只面向技术人员。 |
| C03 | 用户提供资料，知隙围绕资料主动检验用户是否学会。 |
| C04 | 以知隙主导检验为主，同时支持用户主动提问和参与对话。 |
| C05 | 需要模拟面试这类对话场景。 |

| C07 | 自动从用户选择的资料中提取知识点，生成可查看与调整的待办清单，并根据知识点重要程度及用户掌握情况动态安排提问。 |
| C08 | 每个知识点的一次检验默认包含 1 个主问题和最多 2 次追问；达到上限后不能继续自动追问该知识点。 |
| C09 | 以事先列出的必备要点为依据：独立正确覆盖全部要点，且无未澄清的关键错误、判断依据充分时，该知识点才完成本轮检验。 |
| C10 | 为每次回答的处理回合设置模型调用、工具调用、联网搜索和耗时上限；预算用尽仍无法完成判断时保留回答，不强行给出掌握结论。 |

### 3.2 本文采用的建议和假设

以下内容用于让方案可讨论，尚不是最终决定：

- 默认以用户选择的资料和范围组织问题；是否提供资料外拓展题由用户选择。
- 先检索用户资料，在必要时联网补充核验；来源不一致时分别展示。
- 日常检验以文本对话为基础，语音输入和语音播报逐步加入；实时语音方案另议。
- 使用 RAG 或其他适合资料规模的检索方式提供上下文，先不强制引入知识图谱。
- 允许记录检验结果和后续复测，但具体数据保存、删除和版本策略仍需确定。

### 3.3 用词约定

- **上传资料**：用户向知隙提供资料，可能是选择本地文件等方式；该词不预设文件一定上传到远程服务器。
- **资料依据**：来自用户提供资料的相关内容及可定位来源。
- **外部依据**：通过联网检索并核对的公开来源。
- **回答依据**：用户本轮实际说过或提交的内容。
- **盲点**：某个知识点存在尚未解释清楚、与现有依据有出入或需要进一步确认的情况，不等同于对用户整体能力的定论。
- **检验范围**：本轮选择的资料、章节、主题或其他边界；未检验的内容不能被判定为已掌握。
- **知识点待办清单**：从所选资料中提取、供用户查看和调整的知识点集合；每个知识点应能作为相对独立的检验对象。
- **知识点的一次检验**：围绕同一个知识点提出 1 个主问题，并在需要时提出最多 2 次追问；它不同于包含多个知识点的整轮检验。
- **必备要点**：针对某个知识点，在出题前根据资料列出并可供核对的必要内容。它们用于判断本次回答覆盖情况，不代表系统已完整识别整份资料。
- **回答处理回合**：从用户提交一次回答开始，到系统返回反馈或下一问题结束的处理过程；该回合内的模型、工具调用和耗时受到独立预算限制。

## 四、主要使用场景

### 场景 S01：根据资料主动检验

用户提供资料并选择或确认检验范围。知隙自动提取知识点并生成待办清单，根据重要程度和用户表现安排问题；回答后结合资料检索结果评价，必要时在追问上限内继续澄清，完成的知识点移入已完成记录。

### 场景 S02：用户主动调整或提问

检验过程中，用户可以要求切换重点、调整难度、重新解释问题，或者询问某条判断的资料依据。交互仍围绕本轮检验目标。

### 场景 S03：联网核验补充内容

用户的回答包含当前检索结果没有覆盖的内容，或资料与其他信息可能存在冲突。知隙按需使用联网工具查找来源，核对后区分资料依据与外部依据；找不到充分依据时保留不确定性。

### 场景 S04：模拟面试

用户设置所需的面试或口试场景。知隙连续提问，并根据回答追问；结束后结合实际回答与可用依据提供复盘。求职面试、课程口试等场景的侧重点可以不同。

### 场景 S05：复查与复测

用户回看之前的检验记录和待确认内容，选择某个知识点再次检验。新的结果与旧记录关联，仅反映本次覆盖的问题及回答。

## 五、功能需求

以下列出已确认的功能规则及建议细化。能力方向是否已确认，以第三章和各功能中的状态标记为准；未明确确认的具体交互与首版取舍仍需讨论。

### F01 资料提供与处理

**目标**：让用户提供学习资料，并知道哪些内容可以被检验。

建议需求：

1. 支持用户选择资料，显示资料名称、处理状态和失败原因。
2. 提取可用于检验的内容，并尽量保留文件、章节和页码等可用定位信息。
3. 将处理失败、部分成功和处理完成区分展示；无法读取的部分不能被当作已完整解析。
4. 允许用户选择本轮使用的资料、章节或主题。
5. 资料更新后的记录如何关联原始版本，需要在设计阶段明确。

**待确认**：首版文件类型、大小与数量限制；扫描件、图片、表格、公式及 PPT 等内容是否必须支持；资料保存位置与保留期限。

### F02 知识点待办清单与动态提问

**已确认**：知隙从用户选择的资料中自动提取知识点，生成待办清单，并根据重要程度和用户掌握情况主动安排检验。

1. 每个知识点应能查看名称、资料来源、重要程度、当前状态，以及相关的问题、回答和判断依据。来源定位按实际解析结果展示，不编造章节或页码。
2. 用户可以查看和调整清单，例如修改名称、补充、合并或排除知识点；不要求用户必须逐项确认后才能开始检验。清单及范围改变时应明确当前检验范围。
3. 知隙动态安排提问顺序，综合考虑知识点重要程度、用户指定的目标和当前回答表现；重要性判断不应仅依赖资料中出现的次数。尚未检验不等于不会，也不等于已经掌握。
4. 提问应能关联资料依据，并可根据知识点检查理解、解释或应用，不只比较原文措辞。安排顺序应兼顾尚未检验的内容，避免持续追问少数知识点而遗漏其他项目。
5. 每个知识点的一次检验包含 **1 个主问题、最多 2 次追问**，最多对应 3 次正式作答；证据充分时可以提前完成，不必凑满次数。每次只提出一道检验问题，不得通过合并多道独立题目绕过上限。
6. 到达追问上限后，结束该知识点的本次检验：未满足完成标准的项目保留为待巩固或待确认，系统转到其他项目；如果没有其他可检验项目，则结束本轮并显示仍待处理的知识点。同一轮不得自动重置次数并反复检验同一知识点。用户之后主动选择重新检验时，可开始一次新的检验并重新计数。
7. 请求重述题意、模型或工具失败后的同一回答重试，不应被当作新增追问或新增正式作答；用户跳过、表示不会和提前结束应分别记录。
8. 通过完成标准的知识点移出待办主视图，进入可回看的已完成记录。跳过、待巩固和待确认都不算已掌握；清单进度与清空条件见 F09。
9. 默认依据所选资料组织题目；是否使用外部信息生成拓展题由用户选择，具体入口待定。整轮题目总数不固定，旧版的“五个主问题”不是本次默认规则。

知识点清单可能遗漏、重复或拆分不合理；资料解析或清单提取不完整时，应说明未处理范围，不能将清单宣称为整份资料的完整覆盖。具体排序算法和重要程度的计算方式待设计与验证。

### F03 对话与主动权

**目标**：保持知隙主动检验，同时让用户能够参与和控制。

建议需求：

- 知隙可以主动提问，根据回答决定是否追问。
- 用户可以直接提问、要求解释题意或判断依据，也可以改变范围或停止。
- 用户可以选择继续当前话题或转向其他内容。
- 用户请求解释时，可以围绕已有资料和检验依据作答；不要求每次对话都转变为教学课程。

### F04 回答评价与盲点

**目标**：评价用户的实际回答，而不是只比较是否包含预设关键词。

**已确认的完成标准**：

1. 在出题前，根据相关资料为该知识点列出可核对的必备要点及来源；若要点范围过大，应拆分知识点或先澄清范围，用户可以查看和纠正。
2. 必备要点覆盖率 = 用户在本次检验中独立、正确说明的必备要点数 ÷ 事先列出的必备要点总数。主问题与追问中的独立回答可以累计；必备要点为空或来源不足时，不能计算为 100%，应标记待确认。
3. 覆盖率达到 **100%**、没有尚未澄清的关键错误，且资料或可靠外部来源足以支持判断时，标记该知识点为“本轮已掌握”。该指标只表示预先列出的要点在本次回答中的覆盖情况，不是整个学科的客观掌握百分比。
4. 用户使用不同措辞表达同一意思时应按语义评价，不应仅因缺少关键词判错；开放性问题允许多种有依据的合理观点。
5. 知隙已通过提示、讲解或反馈直接给出某个答案后，用户仅复述该答案不能直接算作对该要点的独立掌握。可在剩余追问额度内用不同问题验证；仍无法独立验证时保留待确认或待复测。
6. 回答未覆盖全部要点时，可在追问额度内继续澄清；达到上限后结束本次检验。资料证据不足、来源冲突尚未解决或系统无法可靠判断时，标记待确认，不强行判为已掌握或不会。
7. 评价应区分已说明、未说明、有出入和证据不足，展示用户原回答及资料或外部依据，并允许用户补充、提出异议或纠正。用户主动表示不会与跳过应分别记录。

上述覆盖率依赖必备要点提取和模型判断的质量；即使达到阈值，也只反映本次已检验范围内的结果，不保证对未覆盖内容或长期保持情况的判断。

### F05 资料检索与证据展示

**目标**：使问题和评价可以回溯到资料与用户原回答。

建议需求：

- 在出题和评价时，获取与当前任务相关的资料内容；内容较短时可直接使用完整上下文，较长时可使用检索增强生成（RAG）。
- 展示资料来源和相关内容，并在可靠获取时显示章节、页码或其他定位信息。
- 将“资料原文”“用户回答”和“系统的判断解释”区分开。
- 引用应能够对应实际来源；无法定位时不要编造页码、原句或出处。
- 本轮没有检索到依据，不等同于已经确认整份资料没有相关内容。
- 单纯展示引用不能证明判断一定正确；资料解析、检索、模型理解和引用关系均需验证。

### F06 联网搜索与外部核验

**方向：已确认允许联网搜索；以下细节为建议。**

建议需求：

1. 为 Agent 提供联网搜索能力，并在需要时读取来源正文；具体工具或服务尚未选型。
2. 在资料依据不足、用户要求核验、资料可能过时或来源存在冲突时，Agent 可以决定是否调用工具。
3. 搜索结果应作为待核对的候选来源；不能仅凭搜索结果标题或摘要就宣称核验完成。
4. 优先考虑与问题适用条件相符、来源可核实、具有适当权威性和时效性的资料。
5. 明确标注每项依据来自用户资料还是外部来源；外部来源应有可打开的链接及可用的标题、时间等信息。
6. 资料与外部来源不一致时，呈现差异和适用条件；无法判断时保留待确认状态。
7. 搜索失败、网页无法访问或未找到可靠来源时，应明确说明，不能伪造链接、正文或核验结果。
8. 外部核验不自动改变用户原始资料。是否将外部资料保存为新资料，由后续交互设计确定。

### F07 模拟面试与口试

**方向：已确认需要面试类对话；以下细节为建议。**

- 用户可以设置面试或口试场景、主题和重点；是否需要填写岗位或提供额外资料视具体场景决定。
- 知隙连续提问，并根据用户回答选择追问。
- 用户可以结束对话并查看复盘；复盘应关联实际问题、回答和可用依据。
- 客观知识可以结合资料及外部来源核验；经历、观点和开放性表达应说明评价角度，不冒充唯一标准答案。
- 是否支持无资料直接开展通用模拟面试、评价何时出现以及具体评分方式，待确认。

### F08 语音输入与语音对话

**状态：用户提出了语音需求，具体能力和阶段尚未确认。**

可讨论的能力：

1. 语音输入：录音后转换为文字，供用户确认、修改和提交。
2. 语音播报：将知隙的问题或反馈读出，与语音输入结合后形成轮流对话。
3. 实时语音对话：支持更连续的语音交流；是否要求实时响应、打断和自动判断说话结束，需要单独确定。
4. 文字输入与文字记录可作为补充交互方式。
5. 如果语音识别或播报使用外部服务，应向用户说明相关数据会发送给相应服务；音频是否保存、保存多久需另行确定。

建议先确认语音输入与播报是否属于首版，再决定是否需要实时语音。

### F09 检验记录、纠错与复测

**目标**：让用户清楚待办进度，回看知识点的检验依据，并在需要时再次检验。

**已确认的清单与完成语义**：

- 知识点至少应能区分未检验、检验中、待巩固、待确认、待复测、暂时跳过和本轮已掌握；未检验、跳过或系统判断未完成不等同于不会或已掌握。
- 记录所选范围、知识点、重要程度、事先列出的必备要点、问题、回答、追问次数、评价、资料依据和外部来源。已完成项目移入可查看的记录，不因移出待办视图而删除。
- 用户可以对知识点或评价进行纠正、补充，并保留可理解的历史关联；可以选择某条记录或知识点发起新的检验，新问题和新回答独立记录。
- 当前清单的完成进度可按“本轮已掌握的知识点数 ÷ 当前检验范围内的知识点总数”展示；总数为 0 时不显示 100%。该比例是清单进度，不是对用户整体能力的百分比评分。
- 只有当前检验范围内至少有一个知识点，且所有知识点都按 F04 达到“本轮已掌握”，才能显示清单已完成。待巩固、待确认、待复测、检验中或暂时跳过的项目不能算作完成；筛选视图为空也不能触发完成提示。
- 提示语限定为“当前范围内的知识点均已达到本轮检验标准”。用户调整范围或排除项目时，应明确显示实际范围及被排除的数量；解析或提取不完整时，应说明未处理范围，不能宣称整份资料已经掌握。
- 已接受的用户回答应在处理中断、模型失败或预算耗尽后保留；支持用户回看，并在可行时基于原回答重试，具体持久化与恢复机制待技术设计确定。

已接受回答的保留是上述基本要求；记录和总结的呈现形式、其他数据的保存策略，以及是否需要定时提醒，仍需后续确认。

### F10 Agent 工具与执行边界

**目标**：让 Agent 使用工具支持检验，实际工具权限由应用控制。

建议至少考虑以下工具能力：

| 能力 | 建议用途 |
| --- | --- |
| 资料检索 | 根据问题或回答查找用户选定范围内的内容与来源。 |
| 联网搜索 | 获取可能相关的公开来源。 |
| 网页读取 | 核对来源正文；若选用的搜索工具已提供可核对内容，可按其能力设计。 |
| 检验记录 | 由应用登记问题、回答、依据和评价；实际写入权限和调用方式待技术设计确定。 |

Agent 可以提出工具调用并使用结果继续检验；应用应限制可调用工具、允许访问的资料范围和工具参数。用户资料和网页内容属于待分析数据，不能自动获得修改系统规则或扩大工具权限的能力。

**回答处理回合的默认执行预算**：

| 预算项 | 初始上限 | 计数范围 |
| --- | --- | --- |
| 模型调用 | 4 次 | 处理同一次用户回答的模型请求总数；失败的请求也计入。 |
| Agent 工具调用 | 5 次 | 包括资料检索、联网搜索、网页读取等；失败的调用也计入。用于保存用户回答和运行状态的应用内部持久化不依赖剩余的 Agent 工具预算。 |
| 联网搜索 | 2 次 | 计入上述 5 次工具调用，而不是额外增加的额度。 |
| 回合总耗时 | 60 秒 | 从用户提交回答开始，到返回反馈或下一问题为止，包含模型和工具处理时间。 |

以上是已讨论的可调整初始值，并非经过实测得出的最优配置；是否提供用户侧配置入口待确定。

当调用次数已用完而判断仍需更多请求，或达到时间上限时判断尚未完成，应停止派发超出预算的模型与工具请求，保留已接受的回答和执行状态，并明确提示本次判断未完成或证据不足；不能将系统超时或预算耗尽直接判为用户不会或已掌握。若已在预算内获得充分结果，则正常返回，不能仅因恰好用完额度就判为失败。可允许用户手动基于同一回答发起新的处理尝试，不增加追问或正式作答次数。

对于无法立即取消的外部请求，应用应尽力取消并阻止迟到结果覆盖已经结束或更新的状态；60 秒是该回合的处理预算，不保证所有外部服务都会在截止时实际停止运行。

## 六、资料、来源与数据原则

### 6.1 资料和网络来源如何参与判断

1. 所选资料用于确定本轮主要检验范围。
2. 资料内容是判断的重要依据，但资料本身也可能存在错误、过时或不同版本。
3. 外部资料可以补充核验，也可能与用户资料相冲突。
4. 系统应分别呈现来源及各自支持的结论，不因某个来源被检索到就自动将其视为绝对正确。
5. 无法获得足够依据时，保留不确定性并允许用户继续补充。
6. 资料原文、用户回答、来源链接、检验结论之间应保留可追溯的关联。

### 6.2 数据与隐私

以下为建议的产品要求，具体部署方式待确认：

- 用户应能理解资料、回答、语音和搜索词分别会发送给哪些服务。
- 联网搜索应尽量使用完成检验所需的最少信息，避免直接把完整私人资料或回答作为搜索词。
- 可对用户资料、记录和工具的访问范围进行约束；网页和资料里的指令性内容不应自动获得工具权限。
- 检验记录、资料和音频的保存、查看、删除、导出、备份与保留时长需要明确规则。
- 如果使用远程模型，相关上下文会发送给所配置的模型服务；本地保存资料并不自动意味着模型推理完全离线。

## 七、RAG 与知识图谱的建议

### 7.1 RAG

建议具备基于资料检索的能力：在资料较长时检索相关内容，并把来源上下文用于出题与评价。资料较短、能够合理放入模型上下文时，也可以直接使用所选内容。

具体采用关键词检索、向量检索、混合检索或其他方法，应根据资料类型、检索质量、成本和实际验证决定。当前不预设某种方案一定更优，也不把 RAG 等同于评价准确性的保证。

### 7.2 知识图谱

知识图谱可以用于表达知识点之间的前置、关联或跨资料关系；如果以后需要围绕这些关系安排检验，可再评估引入。

建议首版不把知识图谱作为必要前提。资料、章节、问题、回答、评价及来源的关联可以先用普通结构化记录表达。知识点列表或章节目录也不自动等同于知识图谱。

**待确认**：是否需要跨资料的前置知识关系、关系可视化或基于图谱的检验；图谱的来源和人工纠错如何处理。

## 八、非功能需求

以下为建议，具体指标需要在技术设计和实际测试中确定：

- **准确与可解释**：问题和判断应能回溯到有效依据；错误或不确定情况应如实展示。
- **可用性**：用户能看懂当前是在出题、等待回答、检索、核验还是生成反馈。
- **可靠性**：解析、检索、模型或网络失败时明确提示；已经接受的用户回答不应被静默丢弃。
- **可恢复性**：长时间对话中断后，用户能够回看已保存的记录，并按产品设计继续或重新开始。
- **隐私与隔离**：资料和记录的访问范围由应用控制；外部搜索和远程模型调用应有清晰的数据使用边界。
- **可验证性**：能够区分示例、模拟、真实调用结果和尚未核验的推断。
- **适用性**：对于需要多种表达和多种合理观点的学科，不以关键词命中率代替理解判断。

F10 已给出单次回答处理回合的初始执行预算；其他性能目标、并发量、离线能力、系统平台及无障碍要求尚未量化。

## 九、建议的首版范围

本章仅为开发排序建议，不代表用户已确认最终版本划分。

### 9.1 建议优先完成

1. 选择资料、解析内容，提取知识点待办清单并明确本轮检验范围。
2. 按重要程度和掌握情况安排问题，执行每个知识点“1 个主问题＋最多 2 次追问”的默认上限。
3. 使用事先列出的必备要点判断覆盖率，并结合资料检索、按需联网核验展示判断依据。
4. 用户可以主动提问、指出判断问题或结束检验。
5. 保存基本检验记录，展示清单进度，并支持回看。
6. 按回合执行预算处理模型与工具调用，在超限或失败时保留回答。
7. 提供基础的模拟面试对话及结束后的复盘。

### 9.2 建议随后确定或迭代

- 语音输入、语音播报及实时语音对话的具体范围。
- 复测计划、提醒和更完整的历史统计。
- 多格式导出、记忆和提示词管理。
- 跨资料知识关系、知识图谱及可视化。
- 反馈驱动的策略优化和自进化。

## 十一、建议验收场景

以下是对已讨论方向的行为验收建议；语音及历史需求是否验收取决于最终纳入范围。

| 编号 | 场景 | 建议通过条件 |
| --- | --- | --- |
| A01 | 用户提供可处理的资料 | 能看到处理状态并选择检验范围；解析失败或部分失败时不会显示为完整成功。 |
| A02 | 基于资料开始检验 | 知隙提出与所选范围相关的问题，并能在评价时关联可靠的资料依据。 |
| A03 | 用户换一种方式正确表达 | 系统评价其实际含义，不仅因为未出现预设关键词而判错。 |
| A04 | 回答不完整或有歧义 | 反馈说明已覆盖和未说明的部分，必要时追问或标记待确认。 |
| A05 | 用户回答包含资料外的信息 | 系统不把“当前未检索到”直接当作错误；可按需联网查找并区分外部依据。 |
| A06 | 用户资料与外部资料冲突 | 展示双方可核对来源和差异；无法确定时不捏造最终结论。 |
| A07 | 搜索或网页读取失败 | 明确说明外部核验未完成，不编造链接或来源内容。 |
| A08 | 用户质疑评价 | 用户可查看来源和自己的回答，并补充说明或纠正；历史如何保留符合最终约定。 |
| A09 | 结束并回看检验 | 可回看已保存的问题、回答、判断和依据，并区分未检验内容。 |
| A10 | 模拟面试 | 系统能够进行连续问答和必要追问，并基于实际回答提供复盘。 |
| A11 | 工具遇到资料或网页中的指令性文本 | 应用的实际权限边界不由该文本改变；不可访问的资料和工具仍被程序拒绝。 |
| A12 | 语音能力（若纳入） | 验证录音、识别、修改或提交及失败反馈；播报和实时能力按最终确定范围单独验收。 |
| A13 | 生成知识点清单 | 从所选资料提取可查看、调整并关联来源的知识点；解析或提取不完整时明确提示未处理范围。 |
| A14 | 动态安排问题 | 能结合重要程度和用户回答表现调整顺序；未检验不显示为不会，其他待检验项目不会因反复追问少数知识点而长期被忽略。 |
| A15 | 限制单个知识点的追问 | 一次检验最多 1 个主问题和 2 次追问；达到上限仍未通过时保留待办状态并转到其他项目，同一轮不自动重置计数。 |
| A16 | 提前达到完成标准 | 用户独立、正确覆盖全部预先列出的必备要点，且依据充分、无关键错误时，知识点可提前完成，无需凑满追问次数。 |
| A17 | 辅助回答与证据不足 | 仅复述知隙给出的答案不能直接算作独立掌握；无必备要点、资料不足或来源冲突尚未解决时不能按 100% 通过。 |
| A18 | 清单完成与范围 | 只有当前范围内至少一个知识点且全部达到本轮完成标准时显示清单完成；跳过和筛选视图为空不能冒充完成，排除项及未处理范围清晰展示。 |
| A19 | 模型与工具调用预算 | 一次回答处理回合的模型调用不超过 4 次、Agent 工具调用不超过 5 次，其中联网搜索不超过 2 次；计数包含失败调用。 |
| A20 | 超时、预算耗尽与手动重试 | 在预算用尽且判断尚未完成时停止派发超额请求、保留用户回答并提示判断未完成；预算内恰好完成可正常返回。手动重试同一回答不增加追问或作答次数，迟到结果不能覆盖较新的状态。 |
| A21 | 已完成记录与再次检验 | 达到标准的知识点移出待办主视图但仍可回看原回答和依据；用户主动再次检验时建立新记录并重新计数。 |

建议准备覆盖多个学科、不同表达、资料缺漏、版本冲突和开放性回答的人工核对样例，分别检查资料解析、检索、引用和最终判断。模型生成的评价不能单独作为自身效果已经成立的证据。
