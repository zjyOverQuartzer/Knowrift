这份文档用于指导重新开始开发的知隙。旧项目可供参考，但不作为必须迁移的实现。

**版本约定**：本文件由 V0.4 另存为 V0.5 并吸收后续确认；继续调整时创建新版本，不覆盖既有版本。

- **已确认**：用户明确选择的产品方向、行为或版本范围。
- **建议默认值**：用户委托设计的默认方案或实现建议，仍须开发和测试验证。
- **待实测**：需要通过样例、软硬件与实际服务联调才能决定的指标或具体实现，不表示用户尚未回答。

## 二、产品定位与目标

### 2.1 一句话定位

知隙是一款面向不同学习者的知识检验助手：用户提供自己已经学习过的资料时，知隙自动提取知识点并生成待办清单，结合重要程度和掌握情况主动提问、追问，通过资料和外部依据进行反馈。模拟面试也可以仅根据用户设置的岗位和场景直接开始。

### 2.2 目标用户

面向有自我检验需求的人，不限定专业、行业或年龄，例如：

- 学生：检验自己对课程资料、复习笔记或知识点的理解。
- 自学者：根据书籍、笔记或其他资料进行回顾与自测。
- 求职者或职场人士：围绕准备过的内容进行口述练习和模拟面试。

以上只是例子，不作为限定用户群体或首版支持学科的承诺。

### 2.3 核心目标

1. 让用户以自己的学习资料为主要范围，检验是否能够理解和表达相关内容。
2. 以知隙主动发起问题和追问为主要交互方式，同时允许用户主动提问、指定重点和调整过程。
3. 给出能够回溯用户回答、资料原文和外部来源的判断依据。
4. 对证据不足、不同表达和开放性问题保持审慎，允许用户纠正判断。
5. 将知识点组织为待办清单，按重要程度和用户表现动态安排检验，清晰展示完成进度。
6. 为每个知识点设定追问上限和完成标准，避免持续循环；支持模拟面试，并为后续复查与复测保留记录。

**边界**：知隙以检验已有学习成果为主要用途。解释问题、说明判断依据和应用户请求进行讨论可以支持，但系统性讲课或替用户制定学习课程不是本轮确定的核心目标。

### 2.4 衡量价值的方向

建议通过真实使用和人工核对检验以下问题，而不预先声称产品已经达到某种学习效果：

- 问题是否围绕用户选择的资料和目标。
- 追问能否帮助澄清用户的回答。
- 评价是否准确反映用户所说的内容，并能提供可复查的依据。
- 用户能否区分资料内的内容、外部核验信息和尚待确认的问题。
- 用户能否依据记录再次检验之前不明确的知识点。

### 3.2 委托设计的默认值与实现假设

- 默认使用当前用户的本机数据目录、有限数量的本地备份和加密密钥；音频、恢复及密钥提醒的建议默认值见第六章和 F11。
- 先使用所选资料作为主要检验范围；外部核验和拓展题分别由用户控制。
- 知识图谱是首版功能，具体存储技术、关系类型和图形展现形式按功能与资源要求设计；图谱和 RAG 的结果均需可追溯并接受用户纠正。
- 依赖版本、具体模型、服务商、兼容性和性能指标需实际测试；本文件中的建议不等于测试结论。

### 3.3 用词约定

- **上传资料**：用户向知隙提供资料，可能是选择本地文件等方式；该词不预设文件一定上传到远程服务器。
- **资料依据**：来自用户提供资料的相关内容及可定位来源。
- **外部依据**：通过联网检索并核对的公开来源。
- **回答依据**：用户本轮实际说过或提交的内容。
- **盲点**：某个知识点存在尚未解释清楚、与现有依据有出入或需要进一步确认的情况，不等同于对用户整体能力的定论。
- **检验范围**：本轮选择的资料、章节、主题或其他边界；未检验的内容不能被判定为已掌握。
- **知识点待办清单**：从所选资料中提取、供用户查看和调整的知识点集合；每个知识点应能作为相对独立的检验对象。
- **知识点的一次检验**：围绕同一个知识点提出 1 个主问题，并在需要时提出最多 2 次追问；它不同于包含多个知识点的整轮检验。
- **必备要点**：针对某个知识点，在出题前根据资料列出并可供核对的必要内容。它们用于判断本次回答覆盖情况，不代表系统已完整识别整份资料。
- **回答处理回合**：从用户提交一次文字回答，或实时口述的一次发言结束后启动处理开始，到系统返回反馈或下一问题结束的处理过程；该回合内的模型、工具调用和耗时受到独立预算限制，不是对整个实时面试时长的限制。

## 四、主要使用场景

### 场景 S01：根据资料主动检验

用户提供资料并选择或确认检验范围。知隙自动提取知识点并生成待办清单，根据重要程度和用户表现安排问题；回答后结合资料检索结果评价，必要时在追问上限内继续澄清，完成的知识点移入已完成记录。

### 场景 S02：用户主动调整或提问

检验过程中，用户可以围绕当前知识点要求调整难度、重新解释问题，或者询问某条判断的资料依据。用户不能中途自由切换到其他知识点或主题，但可以退出当前主题并选择是否保存本次进度。

### 场景 S03：联网核验补充内容

用户的回答包含当前检索结果没有覆盖的内容，或资料与其他信息可能存在冲突。用户开启联网核验后，知隙可按需查找来源，核对后区分资料依据与外部依据；找不到充分依据时标记待确认。

### 场景 S04：模拟面试

用户设置所需的面试或口试场景，可以选择已上传资料，也可以不提供资料直接开始。知隙连续提问，并根据回答追问；结束后结合实际回答与可用依据提供复盘。求职面试、课程口试等场景的侧重点可以不同。

### 场景 S05：复查与复测

用户回看之前的检验记录和待确认内容，选择某个知识点再次检验。新的结果与旧记录关联，仅反映本次覆盖的问题及回答。

## 五、功能需求

以下列出已确认的功能规则及建议细化。能力方向是否已确认，以第三章和各功能中的状态标记为准；未明确确认的具体交互与首版取舍仍需讨论。

### F01 资料提供与处理

**目标**：处理用户提供的学习资料，让用户知道哪些内容可用于检验。

1. 首版支持 Markdown、PDF、Word；Word 的 .doc 与 .docx 均为目标格式，必须按选定版本实际验证兼容性。支持扫描版 PDF，以及文档内文字、公式、表格、图片和图表，不将独立 PNG、JPG 等图片列为上传格式。
2. 每份资料不超过 10 MB，界面按 1 MB＝1,000,000 字节说明；Markdown 正文和本次关联的本地图片文件合计不得超过 10,000,000 字节。PDF 和 Word 以包含内嵌内容的文件大小计量。批量上传逐份检查；其他总量限制及远程图片引用策略在详细设计中明确。
3. 使用本机 MinerU 处理需要解析的资料；Markdown 可直接读取后进入提取和检索流程。默认处理所选资料全部内容；若用户选择范围或因工具限制、异常只处理部分内容，必须明确已处理与未处理范围，不能默报整份成功。
4. 对扫描文字、公式、表格和图片进行提取与处理，保留原图或原页以及可用的章节、页码或其他定位。提取成功不等于图表含义一定正确；用户应能与原文核对。
5. 图片或图表解析失败、结果不确定时标记待确认，允许用户补充或纠正；若用户已配置具备看图能力的模型，可由用户手动使用它辅助。使用远程模型前提示相关图片会发送到服务商并可能产生费用；未配置、拒绝或失败时保留原图和待确认状态。
6. 区分处理中、成功、部分成功、失败和取消等状态。解析在本机后台执行，提供进度、取消与失败反馈，可限制并发与资源占用；后台处理仍可能导致资源紧张或卡顿，实际响应性、内存和耗时须在目标设备上测试。
7. 首次使用 MinerU 时，经用户确认后自动下载所需本地模型；取消或下载失败时提示原因和重试方式，不能宣称解析完成。模型大小、来源、运行设备和再分发许可按实际版本核验。

**解析质量验收**：先选取约 20 份有代表性的 Markdown、Word、文本 PDF、扫描 PDF 和含公式、复杂表格、图片／图表的资料，包含多页和接近大小上限的样例，人工逐类对照原文。文字可用约定归一化后的字符错误率；公式统计等价错误或遗漏，表格检查内容、行列及合并关系，图片／图表检查提取、定位、数据和含义。分别记录漏页、阅读顺序、无法评价及错误，依据实测再确定各项合格线。约 20 份样例不代表覆盖所有文档。

### F02 知识点待办清单与动态提问

**已确认**：知隙从资料提取知识点，建立可查看、调整的待办清单，结合知识图谱、重要程度及掌握情况动态安排问题。

1. 每项展示名称、资料来源、重要程度、状态及关联问题、回答、判断依据；页码、章节和引用只能来自实际可用的定位。用户可查看和修改名称、补充、合并或排除，范围变化和被排除内容应清晰显示；检验过程中不得利用调整或排除绕过手动切换限制。
2. 排序综合用户目标、重要性、已知掌握情况以及有依据的前置关系；不能只用词频表示重要程度。未检验不等于不会或已掌握，尚待确认的关系不能冒充已证实的前置条件。图谱循环、依据不足等情形按 F17 处理。
3. 每个知识点一次检验为 **1 个主问题、最多 2 次追问**，最多 3 次正式作答；证据充分时提前结束，每次只问一道检验问题。不得合并多个独立问题绕开上限。
4. 达到上限仍未掌握，标记待巩固或待确认，由系统自动进入同主题下一项；用户明确表示不会时，不必继续追问，标记待巩固后自动进入下一项。都不视为用户自由选择其他知识点；无下一项时结束本轮并展示未完成内容。
5. 同一轮不得对同一知识点自动重置次数反复检验。用户之后主动发起重新检验，创建新记录并重新计数。重述题意及对同一回答的失败重试不新增追问或正式作答。
6. 通过标准的知识点移出待办主视图但保留记录；待巩固、待确认和未检验都不能算已掌握。清单提取不完整、资料未处理完或用户排除内容时，界面需明确实际检验范围。
7. 资料外拓展题默认关闭，用户可在开始本轮时选择开启。需要资料未覆盖的知识才能回答的题目属于资料外拓展；对资料内容换一种措辞或用新例子提问不必然是拓展题。
8. 记录题目是资料内、资料外拓展，还是无资料面试中的模型生成题；同时关联可核对的资料片段或外部标题、链接和支持内容。没有可核实出处时标记“未找到可核验来源”，不能编造引用。日常每题作答后展示该题来源和依据，面试结束后统一展示。
9. 资料外拓展题与联网核验是两个独立开关：关闭拓展题不限制用户另行开启联网核验；关闭联网时不得执行联网核验。

### F03 对话与主动权

1. 知隙主动提出问题并在限制内追问；用户可围绕当前知识点请求重述、提问或质疑依据。
2. 日常检验支持提示和临时解释，记录对应痕迹并标记不熟练、等待独立验证；对已直接告知答案的复述不能算独立掌握。面试模式不提供作答提示和临时知识解释。
3. 当前主题未完成或未退出时，用户不能手动挑选其他知识点、主题、资料或项目；系统按完成、达到上限、明确不会等规则进入下一项仍被允许。
4. 用户主动退出尚未完成的主题时，询问是否保存本次进度：选择保存则保存本次回答、进度、必要状态及时间；选择不保存则丢弃本次会话相对于最近一次用户确认保存进度的新增作答、评价、进度和仅属于本次的恢复草稿或临时录音，并保留之前已保存的记录。新主题没有先前保存记录时，丢弃本次尚未保存的会话数据；不删除原始资料或其他项目记录。
5. 异常中断时自动保留尽可能新的恢复进度，不自动跳转继续；用户从历史记录主动选择恢复，继续尚未完成的提问或处理。恢复草稿与用户确认保存的进度应区分：恢复后若选择主动退出且不保存，仍回退至最近一次确认保存的进度，而不是把临时恢复草稿当作新的永久保存点。
6. 崩溃保护按可恢复的最后检查点记录，不承诺突然断电时最后未落盘的输入或时间精确无损；模型、工具失败后的已接受回答按 F09、F10 保留并支持重试。

### F04 回答评价与盲点

**目标**：评价用户的实际回答，而不是只比较是否包含预设关键词。

**已确认的完成标准**：

1. 在出题前，根据相关资料为该知识点列出可核对的必备要点及来源；若要点范围过大，应拆分知识点或先澄清范围，用户可以查看和纠正。无用户资料的面试可先依据岗位与场景生成候选问题和要点；需要客观核验时应取得适用依据，依据不足则保留待确认，不能伪称来自用户资料。
2. 必备要点覆盖率 = 用户在本次检验中独立、正确说明的必备要点数 ÷ 事先列出的必备要点总数。主问题与追问中的独立回答可以累计；必备要点为空或来源不足时，不能计算为 100%，应标记待确认。
3. 覆盖率达到 **100%**、没有尚未澄清的关键错误，且资料或可靠外部来源足以支持判断时，标记该知识点为“本轮已掌握”。该指标只表示预先列出的要点在本次回答中的覆盖情况，不是整个学科的客观掌握百分比。
4. 用户使用不同措辞表达同一意思时应按语义评价，不应仅因缺少关键词判错；开放性问题允许多种有依据的合理观点。
5. 日常检验中使用提示或接受临时解释，应记录辅助痕迹，并将对应知识点标记为“不熟练”、待独立验证。知隙直接给出某个答案后，用户仅复述该答案不能直接算作对该要点的独立掌握；可在剩余追问额度内用不同问题验证，通过后可以更新状态，但辅助痕迹仍保留。
6. 回答未覆盖全部要点时，可在追问额度内继续澄清；达到上限后结束本次检验。资料证据不足、来源冲突尚未解决或系统无法可靠判断时，标记待确认，不强行判为已掌握或不会。
7. 评价应区分已说明、未说明、有出入和证据不足，展示用户原回答及资料或外部依据，并允许用户补充、提出异议或纠正。用户主动表示不会应与未检验、证据不足或系统未完成判断分别记录。

上述覆盖率依赖必备要点提取和模型判断的质量；即使达到阈值，也只反映本次已检验范围内的结果，不保证对未覆盖内容或长期保持情况的判断。

### F05 资料检索与证据展示

- 使用资料检索能力为出题、评价和知识图谱关系提供相关上下文；内容较短时也可直接使用所选资料。RAG 与图谱相互配合，但均不能保证答案或关系正确。
- 区分资料原文、用户回答、系统判断及外部依据；关联实际可核对的出处和内容，章节、页码不可编造。
- 日常检验每题回答后展示对应问题与判断的来源；面试统一在结束后的复盘中展示。不能只展示链接而不说明它支持什么判断。
- 没有检索到依据不等于整份资料一定没有相关内容；证据不足、来源冲突或解析不完整时标记待确认并允许用户纠正。

### F06 联网搜索与外部核验

1. 首版自行实现免费搜索和公开网页抓取工具，优先使用用户已开启的免费入口；搜索和读取网页正文是不同步骤，具体入口须在允许访问的范围内验证。网页结构、访问限制和网络可能导致免费方式失效，不承诺覆盖全网。
2. 联网核验默认关闭；用户可按需开启，并可对本轮调整。关闭时 Agent 不得调用联网搜索，且与资料外拓展题开关相互独立。
3. 首版支持用户自行配置至少一种可用的搜索 API 作为备选；具体接口和服务商通过中文效果、网络可用性、配置和费用实测确定。Tavily 等可以作为候选，不表示已接入；不同服务的密钥和额度由各自用户配置和承担。
4. 免费源不可用而用户已配置 API 时，提示用户，由用户为本次手动切换；不得悄悄改用可能收费的服务。用户未同意或未配置、服务仍失败时，如缺少充分本地依据则说明原因、标记待确认并继续下一项。若等待用户选择时单次处理预算已耗尽，可基于同一回答手动重试，不增加追问或作答次数。
5. 搜索时只发送完成核验所需的必要查询信息。搜索结果是候选来源，应读取可核对的正文或其他适当原始内容，不凭标题或摘要宣称已核验；外部来源记录可打开的链接、标题及可获得的时间和支持内容。
6. 资料与外部来源不一致时展示双方内容与适用条件；无法判断、链接失效或网页不可访问时不伪造依据，也不自动修改用户原资料。资料是否保存为新资料由用户决定。

### F07 模拟面试与口试

- 首版提供文字模拟面试和口试；用户可设置岗位、场景、主题和重点，并可选择已有资料，也可无资料直接开始。
- 知隙连续提问并根据回答适当追问；同一知识点仍遵循追问上限和提前结束规则。面试过程不提供提示或临时知识解释。
- 面试结束后集中展示问题、实际回答、题目来源、可用判断依据和复盘；开放性观点与经历按适用评价角度反馈，不冒充存在唯一标准答案。
- 无资料时，不伪称题目来自用户资料；需要客观核验但缺少依据时标记待确认。未完成主题时仍按 F03 限制手动切换。
- 实时语音面试属于后续版本，其本地及外部服务与打断规则见 F08。

### F08 语音输入与语音对话

1. 首版日常检验支持语音识别输入和语音播报；仍可使用文字。识别后显示文本，用户可以修改，并须主动确认提交；回答时间在用户结束说话时停止，文字校对和确认时间不计入该次语音作答时间。
2. 日常识别和播报优先使用本地模型，也支持用户配置已有外部语音服务。本地模型首次使用时经用户确认下载；未安装或运行失败而用户配置了外部服务时，提示用户本次手动切换，不自动调用可能收费的服务。
3. 实时语音面试在后续版本交付，优先尝试本地方案，也支持用户配置外部实时语音服务；用户可在 AI 播报时打断，系统停止播报并开始听取用户发言。
4. 实时语音时延先在目标设备和候选服务上实测，再确定验收秒数；持续的整场语音连接不受单次回答处理的 60 秒预算限制。是否达到流畅体验不得在测试前作保证。
5. 使用外部语音服务应明确提示音频或文本将发送给服务商以及可能的费用；本地语音处理不意味着远程大模型和联网核验也离线。原始音频的保存和保留按 6.2 的用户委托默认策略执行。

### F09 检验记录、纠错与复测

- 知识点至少区分未检验、检验中、不熟练、待巩固、待确认、待复测和本轮已掌握；系统未完成判断不等于用户不会。记录资料范围、知识点、来源、必备要点、问题、实际回答、追问与辅助痕迹、评价及依据。
- 本轮进度为本轮已掌握的知识点数除以当前检验范围的知识点总数，总数为 0 时不能显示 100%。只有范围内至少有一项且全部按 F04 达到本轮标准时才可显示清单完成；待巩固、待确认、未检验及筛选后不可见的项目不能冒充完成。
- 完成提示应限定为“当前范围内的知识点均已达到本轮检验标准”；明确显示排除项及解析或提取未完成范围，不推断整个学科或长期保持情况。
- 用户可查看、质疑或纠正评价，并保留与原回答及原依据的可理解关联；之后可主动重新检验知识点，新问题和回答另建记录。
- 系统处理中断、模型失败或预算耗尽时，保留已接受的回答与可恢复状态；用户主动选择不保存本次新增进度是明确例外，按 F03 回退至此前用户确认的保存点。
- 展示逐题回答时间、必备要点覆盖率、清单进度、本轮时长、追问次数和独立／辅助作答次数；不设置总分。计时细节见 F16。

### F10 Agent 工具与执行边界

**目标**：让 Agent 使用工具支持检验，实际工具权限由应用控制。

建议至少考虑以下工具能力：

| 能力 | 建议用途 |
| --- | --- |
| 资料检索 | 根据问题或回答查找用户选定范围内的内容与来源。 |
| 联网搜索 | 获取可能相关的公开来源。 |
| 网页读取 | 核对来源正文；若选用的搜索工具已提供可核对内容，可按其能力设计。 |
| 检验记录 | 由应用登记问题、回答、依据和评价；实际写入权限和调用方式待技术设计确定。 |

Agent 可以提出工具调用并使用结果继续检验；应用应限制可调用工具、允许访问的资料范围和工具参数。用户资料和网页内容属于待分析数据，不能自动获得修改系统规则或扩大工具权限的能力。

**回答处理回合的默认执行预算**：

| 预算项 | 初始上限 | 计数范围 |
| --- | --- | --- |
| 模型调用 | 4 次 | 处理同一次用户回答的模型请求总数；失败的请求也计入。 |
| Agent 工具调用 | 5 次 | 包括资料检索、联网搜索、网页读取等；失败的调用也计入。用于保存用户回答和运行状态的应用内部持久化不依赖剩余的 Agent 工具预算。 |
| 联网搜索 | 2 次 | 计入上述 5 次工具调用，而不是额外增加的额度。 |
| 回合总耗时 | 60 秒 | 从用户提交文字回答，或一次实时口述结束后开始处理，到返回反馈或下一问题为止，包含模型和工具处理时间。 |

以上是已讨论的可调整初始值，并非经过实测得出的最优配置；首版不强制提供用户侧调整入口，具体值应由实现配置并在实测后复核。

当调用次数已用完而判断仍需更多请求，或达到时间上限时判断尚未完成，应停止派发超出预算的模型与工具请求，保留已接受的回答和执行状态，并明确提示本次判断未完成或证据不足；不能将系统超时或预算耗尽直接判为用户不会或已掌握。若已在预算内获得充分结果，则正常返回，不能仅因恰好用完额度就判为失败。可允许用户手动基于同一回答发起新的处理尝试，不增加追问或正式作答次数。

对于无法立即取消的外部请求，应用应尽力取消并阻止迟到结果覆盖已经结束或更新的状态；60 秒是该回合的处理预算，不保证所有外部服务都会在截止时实际停止运行。

面试实时语音可能是一段持续的交互连接；上述 60 秒是单次回答处理回合预算，不应被解释为整场面试或实时音频连接的总时长。等待用户决定是否切换外部服务时，如果预算已经到期，应保留回答；用户作出选择后可手动重试同一回答并开始新的处理预算，不增加追问或作答次数。实时语音的响应延迟及其中工具调用的具体协调方式待设计和验证。

### F11 用户配置模型服务

- 首版先支持 OpenAI 兼容的模型接口；用户在设置界面填写和管理服务商、模型名称、Base URL 与所需 API 密钥，不要求手改配置文件。接口名称不要求用户必须注册 OpenAI，本地兼容服务是否要求密钥以服务本身为准。
- 应提供连接测试、失败原因和能力提示；选择典型服务实际验证文本对话、流式输出及工具调用等所声明能力，不能因为填入地址就宣称兼容所有服务商或模型。资料检索所需的嵌入方式、图片理解和语音服务各自确认能力与配置。
- 图片理解如采用远程模型，必须遵循 F01 的用户手动触发、数据发送提示和失败处理。外部搜索与语音有各自的服务配置和密钥，不假设共用模型密钥。
- 所有需保存的 API 密钥必须加密保存，与普通配置、资料分离；Windows 建议使用当前用户范围的 DPAPI 或等效安全凭据存储。加密不可用时明确报错，不回退明文；密钥不得进入普通日志、默认备份或总结导出。
- 提醒用户定期检查 API 密钥；建议默认每 90 天在应用启动时提示，可调整或关闭。提醒不表示系统已经确认密钥过期、泄露或轮换，应用未运行时不保证按时提示。该提醒不恢复一般学习定时提醒。

### F12 Markdown 总结与导出

- 首版在整轮检验结束后，或用户主动退出并选择保存后，自动根据实际已保存的检验内容生成可编辑的本地 Markdown 总结；关联知识点、实际回答、评价、待巩固／待确认项和可用来源，不能把未完成的内容写成已掌握。
- 用户可按需导出 HTML、Markdown 和 PDF；Word 是资料输入格式，不是已确认的导出格式。检验记录、总结、图表和中文内容的展示与导出效果须实际打开检查。
- 总结调用远程模型可能产生额外费用，应事先提示或在设置中清楚说明；生成失败不能回滚已保存的回答或进度，应显示失败原因并允许用户从记录手动重试。
- 选择主动退出且不保存时，不为被丢弃的本次新增内容生成持久总结；异常中断保留可恢复进度，由用户从历史记录选择继续，不能把中断误称为完成。

### F13 记忆与提示词

- 首版支持查看、编辑、删除个人记忆和项目记忆；每次进入项目时按需读取个人记忆与当前项目记忆，不读取其他项目的专属记忆。项目资料与记忆相互隔离。
- 新发现的长期信息先作为候选供用户确认；用户明确要求“记住”且与现有记忆不冲突时可直接保存。与已有记忆冲突的内容无论是否说“记住”，都应进入候选并提醒，确认前不覆盖原记忆，用户仍可继续使用。
- 提供系统、项目和个人提示词。系统安全基线始终生效且不可编辑；其他系统提示词可编辑。项目和个人提示词都参与当前项目，发生冲突时在安全边界内按项目优先执行，并为需要持久处理的冲突生成候选，不静默覆盖长期配置。
- 候选应展示适用范围、冲突内容及可用来源，允许用户处理；不同项目独立成立的设定不自动合并或互相泄露。以后可增加用户设定的自动冲突处理规则。
- 安全提示词不能单独保证防注入；文档、网页与工具结果是非可信数据，文件、网络和工具访问由应用程序独立检查权限。用户可见的提示词编辑能力不能绕过该安全边界。

### F14 自进化与 Skill 沉淀

**首版范围**：将经核实的反馈和有效流程整理为候选 Skill，记录来源与适用场景，先验证，再由用户决定是否启用；可查看版本、停用和回退。自进化指复用或调整行为指导，不意味着训练模型参数。

1. 每个候选 Skill 启用前至少准备 20 条人工核对的相关问答样例；可以复用适用的已标注样例，但开发集与验收集应分开。样例数不保证实际效果，验证应说明样例范围和模型配置。
2. 与启用前基线对照，展示目标问题的改善以及其他样例的退步，不能仅以模型自评证明改善；若存在退步，如实展示后允许用户自行决定是否启用，安全和工具权限边界仍由程序执行。
3. 默认只在当前项目启用，用户明确选择后可提升为个人通用 Skill；提升 Skill 本身不授权共享各项目资料或记忆。
4. 首版包含上述基础自进化，外部 Skill 导入属于后续版本；后续首批支持 SKILL.md 及参考文件，附带可执行脚本留待后续单独设计运行环境、权限及授权。

### F15 外部 MCP、Skill 与其他工具

- 首版先完成资料检索、联网核验和自进化所需的内置工具；用户接入外部 MCP、外部 Skill 导入和其他外部扩展放到后续版本。
- MCP 是接入外部工具、资源及提示模板的协议。MCP 服务可以提供工具或访问 Skill 内容，但连接 MCP 不会自动实现通用 Skill 发现、验证和执行；后续仍需明确加载、权限、作用范围和管理方式。
- 后续外部 Skill 首批兼容 SKILL.md 和参考文件，附带脚本的执行后续加入。任何已启用的工具仍受应用权限和 F10 回合预算约束。

### F16 回答时间与检验指标

- 文字题在题目显示完成后开始计时，提交文字时结束；播报题在播报结束后开始，语音题在用户结束说话时结束。后续实时面试中若用户打断播报并开始回答，从实际开始回答时计时并记录打断。
- 日常语音转写后的检查、编辑和确认提交时间不混入语音回答时间；模型处理、网页读取和系统反馈时间不混入用户回答时间。
- 异常中断后从历史恢复时保留中断前已记录的回答时间，离线期间不计时。突然断电等情况下只能恢复到最后一个实际保存的检查点。
- 结果页展示本轮总时长、每题回答时间、追问次数、独立／辅助作答次数、必备要点覆盖率和清单进度；辅助过程保留提示或临时解释痕迹。不设置总分，也不以回答快慢单独判定掌握程度。

### F17 知识图谱与提问顺序

**首版范围**：在资料知识点清单基础上，建立可查看和纠正的知识点关系，分析关系并辅助安排提问。

1. 将知识点表示为节点，并记录有意义的关系，例如有方向的前置关系或相关关系；仅列出知识点或章节不等于已经形成关系图谱。关系应能关联实际资料、位置或其他明确允许使用的依据。
2. AI 可自动提取节点与关系，用户可以查看、补充、修改或删除；资料定位无法取得时不编造来源。依据不足、存在冲突或提取失败的关系标记待确认，不作为已核实的强制前置条件。
3. 动态排序综合知识点重要程度、已知掌握情况与有依据的前置关系。关系出现循环、证据缺失或模型判断不可靠时应提示或保留待确认，采用其他可用因素继续排序，不能卡住检验或绕过每点的追问上限。
4. 查看关系时可回到相关知识点与来源，并允许纠正；用户修改资料或图谱后，应说明关系基于的版本并更新或标记需复核的关联。项目间资料、图谱及记忆保持隔离。
5. 图谱的存储方式、具体关系类型、可视化形式和抽取策略在设计与实测中确定；不强制使用特定图数据库，也不以自动关系或图谱节点数量证明评价正确。

## 六、资料、来源与数据原则

### 6.1 资料和网络来源如何参与判断

1. 所选资料用于确定本轮主要检验范围。
2. 资料内容是判断的重要依据，但资料本身也可能存在错误、过时或不同版本。
3. 外部资料可以补充核验，也可能与用户资料相冲突。
4. 系统应分别呈现来源及各自支持的结论，不因某个来源被检索到就自动将其视为绝对正确。
5. 无法获得足够依据时，保留不确定性并允许用户继续补充。
6. 资料原文、用户回答、来源链接、检验结论之间应保留可追溯的关联。

### 6.2 数据与隐私

**已确认**：知隙以 Windows 桌面安装包交付，主要服务随应用在用户本机运行，资料、检验记录及其他业务数据保存在本机。

以下为进一步的产品要求与建议：

- 用户应能理解资料、回答、语音和搜索词分别会发送给哪些服务。
- 联网搜索应尽量使用完成检验所需的最少信息，避免直接把完整私人资料或回答作为搜索词。
- 可对用户资料、记录和工具的访问范围进行约束；网页和资料里的指令性内容不应自动获得工具权限。
- 检验记录、资料和音频的本地目录、查看、删除、导出、备份恢复与保留按以下委托设计的默认规则执行，并通过实际恢复测试验证。
- 如果使用远程模型、联网搜索或其他远程服务，完成任务所需的上下文、搜索词或音频可能发送给相应服务；本地保存资料并不自动意味着所有推理和检索都离线。
- 模型 API 密钥应与普通配置和用户资料分开处理，避免写入普通日志或导出文件。

**本地数据与备份建议默认值**（用户委托设计，仍需按实际安装、空间和恢复测试验证）：

1. 数据建议默认位于当前 Windows 用户的 %LOCALAPPDATA%\Knowrift 目录，避免写入程序安装目录；界面展示实际路径。结构化业务状态可使用 SQLite，按用户空间和项目隔离，最终数据库布局待技术设计确定。
2. 选择导入资料时在应用管理的本地空间保留副本，并关联原来源；删除知隙内的项目或资料默认只删除应用管理的内容，不删除用户原路径中的原始文件。
3. 建议默认不长期保存原始音频，只保留本轮所需的临时音频与对话文字；用户可选择保存录音，建议默认保留 30 天并允许手动删除。具体实时处理中临时文件清理和外部语音服务的数据保留依其服务设置，不能由知隙单方面保证。
4. 建议应用运行时每日首次满足条件时在后台创建一次本机备份，保留最近 7 份，并支持用户手动导出备份至其他位置；备份包含用户确认保存的资料副本、检验记录、记忆、提示词与 Skill 等必要数据。为了遵守主动退出时的“不保存”，自动备份不包含尚未确认保存的本轮恢复草稿，选择不保存后清理本轮草稿及其临时数据。
5. 数据库与相关文件的备份需采用一致性方案，检查备份是否完整；恢复前展示内容，允许恢复为新项目或在用户确认后处理冲突，不能静默覆盖现有数据。
6. 普通备份默认不包含 API 密钥和可重新生成的大型模型缓存；迁移到另一台机器后提示用户重新配置密钥，并按需要重建索引或准备模型文件。同一硬盘上的备份主要帮助恢复误操作，不等于应对硬盘损坏。
7. 用户删除项目时，界面应说明已有历史备份可能仍包含该项目，允许用户管理相关备份；自动清理策略和跨备份彻底删除方式需在实现前细化并测试。

### 6.3 安装与本机服务

- 首版提供 Windows 桌面安装包，由应用管理本机业务、Agent 及 MinerU 服务；不要求用户自行安装全局 JDK、Python 或手动配置运行环境。
- 安装包自带所需 JRE、Python 与依赖；首次使用 MinerU 或日常语音相关功能时，明确提示并经用户确认后自动下载各自所需模型，显示进度和存储需求；支持失败说明与重试。具体组件、模型体积和再分发许可须核对。
- 下载和本地解析、语音处理与远程大模型、联网搜索是独立能力；本地模型安装完成不代表远程服务或大模型调用可以离线。
- 安装验证建议在未配置开发工具的干净 Windows 虚拟机快照或 Windows Sandbox 中检查安装、启动、重启、升级与卸载；真实 Windows 电脑用于验证 CPU 和可用 GPU 模式、近 10 MB 复杂资料的耗时、内存、界面响应、取消及失败恢复。
- 虚拟机检查依赖遗漏，不能代替真实设备性能测试；记录系统版本、硬件配置、模型及依赖版本、测试文档和结果，阈值根据实测确定。

## 七、检索与技术架构

### 7.1 RAG

建议具备基于资料检索的能力：在资料较长时检索相关内容，并把来源上下文用于出题与评价。资料较短、能够合理放入模型上下文时，也可以直接使用所选内容。

具体采用关键词检索、向量检索、混合检索或其他方法，应根据资料类型、检索质量、成本和实际验证决定。当前不预设某种方案一定更优，也不把 RAG 等同于评价准确性的保证。

### 7.2 知识图谱

用户已选择将知识图谱纳入首版：AI 根据资料提取知识点之间的关系并关联来源，用户可以查看和纠正，知隙利用有依据的关系辅助安排提问。关系依据不足时标记待确认。

它与 RAG 分别承担知识关系表达和资料检索的作用，两者都需要经过来源、抽取与判断的验证。图谱的具体实现、数据结构或数据库不预先指定；功能及验收见 F17。

### 7.3 Java、Spring AI 与 Python 的职责比较

**用户已确定**：Windows 桌面应用及主要服务在本机运行；采用 Java＋Spring AI 负责业务和 Agent，Python 主要承接本机 MinerU 解析。

| 部分 | 已确定方向或待验证职责 |
| --- | --- |
| 桌面应用 | 安装、展示交互并管理本机服务；具体桌面框架未确定。 |
| Java＋Spring AI | 负责项目和业务状态、Agent 编排、模型调用、工具调用、检验进度及数据提交；业务规则和权限由应用明确实现。 |
| Python＋MinerU | 主要承担本机文档解析，可通过受控的本机进程或服务与 Java 协作；具体协议和进程方式待设计。 |

用户熟悉 Java，并学过 Python 的 LangChain 和 LangGraph；本项目选择 Spring AI 作为 Java Agent 技术方向，不要求同时再实现一个 Python Agent。“Java 负责业务和 Agent”不等于整个产品完全没有 Python：本机 MinerU 仍需解决相应运行环境、进程或服务及打包。

应先验证 Spring AI 的 OpenAI 兼容服务配置、工具调用与 F10 预算，再验证首版本机 MinerU、日常语音和打包；外部 MCP 与实时语音按后续版本验证。框架提供工具调用能力，不自动保证项目的追问上限、数据一致性或语音兼容性。

## 八、非功能需求

以下为建议，具体指标需要在技术设计和实际测试中确定：

- **准确与可解释**：问题和判断应能回溯到有效依据；错误或不确定情况应如实展示。
- **可用性**：用户能看懂当前是在出题、等待回答、检索、核验还是生成反馈。
- **可靠性**：解析、检索、模型或网络失败时明确提示；已经接受的用户回答不应被静默丢弃；用户明确选择不保存本次进度时按 F03 回退。
- **可恢复性**：长时间对话中断后，用户能够回看已保存的记录，并按产品设计继续或重新开始。
- **隐私与隔离**：资料和记录的访问范围由应用控制；外部搜索和远程模型调用应有清晰的数据使用边界。
- **可验证性**：能够区分示例、模拟、真实调用结果和尚未核验的推断。
- **适用性**：对于需要多种表达和多种合理观点的学科，不以关键词命中率代替理解判断。

F10 已给出单次回答处理回合的初始执行预算；其他性能目标、并发量、离线能力、系统平台及无障碍要求尚未量化。

| A14 | 动态安排问题 | 能结合重要程度、掌握情况与有依据的图谱关系调整顺序；未检验不显示为不会，不因反复追问而忽略其他项目。 |
| A15 | 限制单个知识点的追问 | 一次检验最多 1 个主问题和 2 次追问；达到上限仍未通过时保留待办状态并转到同主题下一知识点，同一轮不自动重置计数。 |
| A16 | 提前达到完成标准 | 用户独立、正确覆盖全部预先列出的必备要点，且依据充分、无关键错误时，知识点可提前完成，无需凑满追问次数。 |
| A17 | 辅助回答与证据不足 | 仅复述知隙给出的答案不能直接算作独立掌握；无必备要点、资料不足或来源冲突尚未解决时不能按 100% 通过。 |
| A18 | 清单完成与范围 | 只有当前范围内至少一个知识点且全部达到本轮完成标准时显示清单完成；待巩固、待确认和筛选视图为空不能冒充完成，排除项及未处理范围清晰展示。 |

| A28 | 总结与导出 | 整轮结束或保存退出时自动生成可编辑的本地 Markdown 总结；能导出并实际打开 HTML、Markdown、PDF，失败时已保存记录不丢失且可重试。 |

## 十二、实测与工程设计待办

本轮需要用户选择的产品范围和主要交互已经确认。以下事项依赖后续设计或实测，不能预先当作达标结果，也不要求现在凭空指定数值：

1. **资料解析与检验质量**：先人工核对约 20 份代表性资料，分别统计文字、公式、表格、图片／图表、来源定位和漏页等错误或遗漏，再确定各项合格线。另准备人工核对的多学科问答样例，检验知识点提取、RAG 引用、图谱关系与最终评价。
2. **本机性能与兼容性**：记录实际 CPU／GPU、内存、系统版本、文档、模型和依赖，验证 MinerU、日常语音、安装包大小及界面响应；分别测试干净虚拟环境与真实电脑。未来实时语音面试的延迟阈值在目标设备实测后决定。
3. **具体服务与接口**：选定并实际联调首版支持的 OpenAI 兼容模型服务、至少一种备选搜索 API、本地及已声明的外部语音服务；验证模型能力、工具调用、中文效果、网络可用性、额度、失败恢复和隐私提示，不预设所有服务均兼容。
4. **知识图谱与检索实现**：确定关系类型、抽取与版本更新方式、图形或列表的交互形式、循环处理、数据存储及检索策略；人工核对关系及出处，验证排序不会饿死或阻塞知识点。
5. **数据与安全**：验证密钥加密、各类外部调用的数据范围、项目隔离、断电检查点、主动放弃时的回退、一致性备份与实际恢复；检查删除后历史备份的管理说明。
6. **安装和依赖**：固定 Java、Spring AI、Python、MinerU、语音模型及各项依赖版本；验证 .doc／.docx、扫描件、下载失败重试及许可，不把文档中的候选组件视为已通过打包。
7. **处理预算**：F10 的调用与 60 秒上限是可调整初始值，应结合实际模型、工具延迟和用户体验验证；仍需保留原回答与可重试路径，不能把初始值误写成实测结论。
