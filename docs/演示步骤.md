# 知隙课程演示步骤

建议在一台 Windows 电脑上展示本地学习流程，再用持续在线的提醒服务展示关机后执行。演示时保留“示例模式”或“真实模型”的实际状态，不把测试桩的分数当作真实效果。

## 本地学习和交付

1. 启动知隙，打开示例 Java 项目，说明数据保存在本地目录。
2. 设置北京百炼接口与 qwen3.7-flash，测试连接，关闭示例模式后新开诊断。
3. 输入 Java 并发主题，展示一次独立回答、追问和提示。打开盲点查看原问题、原回答和判断依据。
4. 结束本轮，打开真实 Markdown 总结，在文件中添加一句自己的说明。再次生成总结，展示原文件与新文件同时存在。
5. 在文件指令中要求读取一份项目资料并写入 summaries/，打开执行记录和真实文件。
6. 勾选部分对话，导出 Markdown、HTML、PDF 和 Word。打开 PDF 选择中文文本，打开 DOCX 编辑段落。

## 用户控制

1. 在记忆页面确认一条候选偏好，再编辑 Markdown 内容，展示用户与项目范围及暂停开关。
2. 在项目提示词中要求先用代码示例，展示当前生效层级；清空项目模板后回退到用户模板。
3. 外部修改同一个文件后，在应用中保存旧版本，展示冲突提示和另存副本，避免覆盖用户修改。
4. 完全退出并重新打开，继续原来的对话和进度。

## 邮件提醒

先部署 backend/cloud/ 服务，配置服务器 SMTP，并在桌面绑定和验证本人邮箱。

1. 离线新建未来任务，展示“待同步”。
2. 联网同步，确认云端已同步，再退出桌面应用。
3. 到期后由服务器发送预备邮件。重新打开桌面查看执行记录，状态只说已提交邮件渠道。
4. 展示暂停和修改同步，以及多个学习项目每天合并的到期摘要。

若尚未部署真实服务，可以运行 cloud.test.mjs 讲解独立调度、重试、去重与恢复测试，明确这是本地测试，不能声称已经完成真实关机发信。

## 反馈如何影响后续行为

1. 选一条有真实记录与资料依据的诊断问题，写明错误和原因并确认核实。
2. 生成候选规则，检查修改内容、来源和范围。
3. 人工核对20条样例，保留开发集与验收集分离。运行真实40次对照，展示改善或退步的实际结果。
4. 只有报告满足门槛才人工启用，下一次诊断使用项目策略。通过历史版本停用或回退。

如果报告没有改善，展示“需要修订”及原因，这同样能说明验证门槛。不能为了完成演示修改分数或绕过人工确认。
