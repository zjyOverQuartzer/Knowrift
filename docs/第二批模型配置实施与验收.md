# 第二批模型配置实施与验收

日期：2026-10-22。分支：`refactor/java-python`。本批不自动提交、推送或发布。

## 交付行为

新版桌面“设置”提供多套配置的新建、修改、删除、连接测试及全局当前配置选择。所有项目共用当前配置，测试其他配置不会切换选择。保存与启用均不发起模型请求，允许未经测试直接启用。删除当前配置后清空选择，不自动启用其他提供商。

Java 保存配置元数据，Electron 加密保存每套配置独立的密钥，Python 负责真实模型 HTTP 请求。Python 不可用时仍可管理配置；Java 不可用时明确显示错误，不回退旧后端。学习、文件业务、流式任务、旧项目迁移及新版 EXE 未纳入本批。

## 启动及操作

在项目根目录的 PowerShell 中执行：

```powershell
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
$env:KNOWRIFT_JAVA_HOME = 'D:\java\jdk-17'
$env:KNOWRIFT_PYTHON = 'D:\SoftWareLearn\Miniconda3\python.exe'
npm run services:setup
npm run desktop:dev:java
```

基础解释器用于项目虚拟环境，依赖版本全部锁定。第二批增加 `httpx==0.28.1`，完整依赖见 `backend/agent/requirements.lock`。已准备好环境后，日常启动只需设置 JDK 17 路径并执行 `npm run desktop:dev:java`。旧版 release 内的 EXE 不包含第二批功能。

打开“设置 → 新增配置”，填写名称、协议、基础地址和实际模型 ID。需要密钥时选择“输入新密钥”；免密服务选择“清除密钥 / 本机免密”。保存后分别选择“测试连接”和“设为当前配置”。修改后的表单须先保存才能测试或启用；切换配置或重新加载会询问是否放弃未保存修改。

## 协议与地址

| 协议 | 基础地址示例 | 最终路径 | 鉴权及请求 |
| --- | --- | --- | --- |
| Chat Completions 兼容 | `https://api.openai.com/v1` | `/v1/chat/completions` | 填写密钥时使用 Bearer；`model`、`messages`、`stream:false` |
| Anthropic Messages | `https://api.anthropic.com/v1` | `/v1/messages` | 默认 `x-api-key`，可选 Bearer；`anthropic-version:2023-06-01`，可选工作区 ID；测试 `max_tokens:1024` |
| Ollama 原生 Chat | `http://127.0.0.1:11434` | `/api/chat` | 本机可免密，填写密钥时使用 Bearer；明确 `stream:false` |

基础地址去除尾部斜杠，再追加该协议的操作路径。界面显示最终请求地址。误填完整操作路径时拒绝保存并提示修正。远程只允许 HTTPS，本机 `localhost`、`127.0.0.1`、`::1` 允许 HTTP；禁止 URL 内的账号、查询参数及片段。远程配置要求密钥，本机免密服务允许留空。

测试仅发送固定短提示“请只回复：连接成功”，不携带项目内容，不注入旧版专有推理参数。有效的非空文本即可成功，无需逐字匹配。返回协议合法并获得文本表示此次连接测试成功，学习诊断、工具和流式能力仍需后续实现和验收。

外部请求维持 TLS 验证，不自动跟随重定向或重试。回环请求绕过系统代理；远程请求遵循标准代理与 CA 环境配置，但不从环境变量读取模型密钥。

协议依据：[Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[Anthropic Messages](https://platform.claude.com/docs/en/api/messages/create)、[Anthropic 鉴权](https://platform.claude.com/docs/en/manage-claude/authentication)、[Ollama Chat](https://docs.ollama.com/api/chat)。

## 数据及凭据一致性

- 全局 `app.db` 升级到版本 2，新增 `model_profiles` 和单行 `model_settings`；每项目数据库仍为版本 1。
- 已有版本 1 的全局库先通过 `VACUUM INTO` 生成 `backups/app-v1-<UUID>.db` 并检查完整性，再在同一事务中应用版本化 SQL；失败回滚。备份失败则不升级。版本 0 的新库依次初始化到版本 2；后续启动不重复备份。
- 配置使用稳定 UUID，重复保存相同内容返回原记录；配置变化递增 `revision`。修改、删除和测试校验预期版本。
- `credentials.json` 仅保存系统 `safeStorage` 加密后的数据，Java 保存命名空间为 `model-profile/<profileId>/<UUID>` 的凭据引用。界面仅接收 `hasKey`，已保存密钥不回显。
- 密钥写入串行执行；先保存新凭据，再提交配置引用，成功后清理旧凭据。响应丢失时读取权威配置核对，无法核对则保留凭据，避免误删。
- 服务就绪后仅清理本批未引用的凭据；读取配置失败时不清理，不接管旧版模型或云端凭据。
- 协议或规范化后的地址变化不能直接保留旧凭据。清除密钥有独立操作。系统加密不可用时拒绝密钥写入，不降级明文。

运行中的一致性备份方式见 [SQLite VACUUM INTO](https://www.sqlite.org/lang_vacuum.html)。本批数据库备份不包含密钥，不能用于跨 Windows 用户迁移凭据。

## API 与桌面桥接

所有 HTTP 接口继续校验本次服务的独立令牌，服务协议版本仍为 1。端口、服务令牌、实例连接信息及凭据引用不进入界面 API。

| 接口 | 请求／返回 |
| --- | --- |
| `GET /api/v1/model-profiles` | `{profiles,activeProfileId}` |
| `PUT /api/v1/model-profiles/{id}` | 完整非密钥字段、`expectedRevision`、内部 `credentialRef`；返回公开配置 |
| `DELETE /api/v1/model-profiles/{id}` | `{expectedRevision}`；原子删除并按需清空选择 |
| `PUT /api/v1/model-settings/active` | `{profileId: UUID或null}`；返回最新配置列表及选择 |
| `GET /internal/model-profiles` | 仅供 Electron 使用的元数据及凭据引用 |
| Java `POST /internal/model-profiles/{id}/test` | `expectedRevision`、临时密钥及当前 Python 实例描述 |
| Python `POST /internal/models/test` | 当前实例标识、配置快照、临时密钥 |

公开配置类型为 `{id,name,protocol,baseUrl,model,anthropicAuth,workspaceId,hasKey,revision}`。Electron 白名单 `modelSettings` 提供 `list/save/remove/activate/test`；保存输入的密钥操作是 `keep/replace/clear`，不会向界面提供密钥读取或任意 HTTP 请求接口。

测试结果为 `{profileId,revision,ok,code,message,preview,latencyMs}`。模型故障作为测试结果返回；本机服务故障、输入或版本冲突使用现有错误封套。区分模型鉴权、路径或模型不存在、限流或额度、TLS、网络、超时、请求拒绝、异常协议及服务不可用。文本预览最多 200 字符并隐藏当前测试密钥；错误不回显上游响应体。

每次测试通过 Electron 获取当前 Python 实例，Java 再认证探活并校验实例、协议与就绪状态，然后调用 Python。普通业务接口仍为 10 秒超时；模型连接为连接 10 秒、总时限 60 秒，Java 等待 65 秒，Electron 等待 70 秒。全局仅一次在途测试，网络等待不持有 SQLite 事务，不阻断项目管理。

配置编辑后旧测试结果不再显示；测试结果不持久化，重启不会自动请求模型。Java 断开连接、服务关闭或父进程退出时取消 Python 在途请求，完全退出沿用首批最多 10 秒的进程回收规则。
