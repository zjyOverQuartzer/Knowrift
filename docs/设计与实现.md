# 知隙设计与实现

## 运行结构

桌面端采用 Electron + React + Vite。渲染进程开启 sandbox 和 contextIsolation，通过白名单 IPC 调用本地服务。文件操作、模型请求、凭据和导出在主进程执行。云端采用 Fastify + Nodemailer + Luxon，独立运行，支持 Docker 部署。

工程使用 npm workspaces：`frontend` 管理 React、Vite 和 TypeScript；`backend` 管理学习服务及云端提醒的运行依赖；根目录管理 Electron、打包和跨层验收。`desktop` 是系统适配层，学习业务通过公开包入口 `@knowrift/backend` 加载。前端构建输出为 `frontend/dist`，桌面发行包同时包含该页面和后端工作区的运行文件。

目录重命名为 Knowrift 不改变中文应用名、appId、IPC 通道和既有环境变量；系统保存的学习记录及凭据继续使用原位置。前端界面代码不直接导入 Node.js 学习业务。开发预览的 Vite 服务端插件调用后端以支持本地预览，生产桌面使用 IPC。

本地目录分为个人配置区与用户授权项目区。会话、盲点、任务和索引使用原子替换的 JSON 文件保存；Markdown 为记忆、提示词和总结的内容源。文件操作使用真实路径边界检查、revision 比较和历史副本。小规模课程服务采用单进程持久化调度，部署时仅运行一个服务实例。

## 界面参考

界面基于 image_gen 生成的完整工作台概念。白色工作区、浅冷灰侧栏、蓝色主操作、左侧项目与功能导航、中间问答、右侧盲点与复习。其他功能使用同一套排版、颜色、控件和编辑器。概念图保存于 design/concept.png，仅作设计参考。

## 模型与数据

默认提供阿里云百炼兼容接口，模型与地址可修改。仅使用明确标识的 DASHSCOPE_API_KEY 进行环境联调，不读取或复用其他服务的环境密钥。桌面用户填写的密钥经 Electron safeStorage 的系统加密后保存，界面只返回是否已配置。

百炼官方文档：https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions

当前官方推荐业务空间专属域名，现有 dashscope 域名仍可使用。地址需与密钥地域、套餐和模型权限匹配，连接测试不等于所有模型能力已通过。

## 自进化

系统保存问题反馈、候选规则、验证记录与启用版本。验证使用人工核对的预期标签；评测结果不能单靠模型自我表扬。启用必须经人工确认，作用范围限定当前项目，支持回退。课程样例用于回归演示，不作为实际学习效果提升的证明。

## 邮件边界

云端保存本人已验证邮箱、已准备的正文、时间规则和执行记录。云端不进行学习分析。SMTP 接受显示为“已提交邮件渠道”。超时等不确定状态不宣称送达。服务端需配置真实 SMTP 并持续运行于用户自选服务器，安装桌面应用本身不会部署云服务。
