## 当前范围

新版提供创建、查看、切换、重命名、归档及取消归档项目，数据由 Java 保存到全局登记库和每项目 SQLite。Python 仅提供服务骨架、认证探活与退出处理。学习、文件管理、模型诊断、流式任务、旧数据迁移及新版安装包留待后续批次。云端提醒继续沿用现有 Node.js 实现。

旧入口 `npm run desktop`、`npm run desktop:dev` 和 `npm run dev` 保留；Java 模式使用独立页面状态及有类型的项目 API。Java 模式不会创建旧示例、启用旧提醒定时器、初始化 Vite 旧预览业务或在服务失败时回退旧后端。

## 开发启动

工作目录为仓库根目录。当前开发机路径如下，其他电脑需替换实际安装位置：

```powershell
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
$env:KNOWRIFT_JAVA_HOME = 'D:\java\jdk-17'
$env:KNOWRIFT_PYTHON = 'D:\SoftWareLearn\Miniconda3\python.exe'
npm ci
npm run services:setup
npm run desktop:dev:java
```

Java 固定 release 17，Spring Boot 4.1.1；项目脚本在子进程中配置 Maven 的 `JAVA_HOME` 和 PATH，拒绝使用其他 Java 主版本。Python 3.14 的基础解释器只用于创建 `backend/agent/.venv`，运行使用该虚拟环境。直接依赖见 `requirements.txt`，完整依赖版本见 `requirements.lock`。

本机实测 JDK 17 在默认 TEMP 位置建立 NIO 内部套接字连接时出现 `Unable to establish loopback connection` / `UnixDomainSockets.connect0: Invalid argument`。启动器在 Windows 下为本次 Java 进程指定仓库 `.cache/java-tmp` 作为 `jdk.net.unixdomain.tmpdir`，已单独验证探活恢复成功；不修改系统 TEMP 或 JDK 配置。该属性的作用见 [Oracle Java 17 网络属性](https://docs.oracle.com/en/java/javase/17/core/java-networking.html)。

本机 pip 默认镜像首次访问失败，切换当前会话的 `$env:PIP_INDEX_URL = 'https://pypi.org/simple'` 后成功下载。没有修改全局 pip 配置。Maven 使用本机已有配置和缓存。

新版开发入口默认设置 `ZHIXI_HOME` 为仓库内 `.data/java-dev`。可用当前进程环境变量覆盖为另一个独立工作区；如果包含旧 `projects.json`，会提示选择独立目录，不自动导入。新版浏览器预览提示通过桌面应用打开。

## 存储与恢复

```text
新版工作区/
  app.db                  # 登记、名称缓存、归档、创建操作
  .service.lock           # Java 实例锁；文件保留不代表服务仍运行
  workspaces/             # 默认项目父目录

项目目录/
  .zhixi/project.db       # 项目身份、名称、创建时间
  .zhixi/creating.id      # 仅初始化期间存在的项目身份标记
  MEMORY.md
  PROJECT_PROMPT.md
  notes/
  references/
  summaries/
  .history/
```

项目名称以项目库为准，登记库名称只用于缓存和不可用状态显示。名称变更不移动目录；归档保存在登记库，文件保留。当前仅支持本机磁盘目录。SQLite 使用 WAL；连接启用外键和 5000ms 锁等待，数据库结构使用 `PRAGMA user_version` 和版本化 SQL 升级，较新结构不会降级。

创建顺序为持久化创建意图、写入独占身份标记、初始化项目库和缺失文件、完成登记，最后移除标记。崩溃后的 pending 操作启动时恢复；目录冲突或权限错误会保留失败记录，用户修复目录后可用同一请求标识重试。仅接管与本次项目 ID 一致的中间产物，不递归删除用户目录，不覆盖已有 Markdown 或普通资料。

路径使用真实路径与 Windows 大小写规范化，包括 `.zhixi` 的目录联接检查。旧 JSON、新项目库和初始化标记双向冲突检查；旧版也拒绝接管含 `app.db` 的新版全局工作区。单项目目录缺失、权限不足、数据库损坏和结构不兼容不会拖垮项目列表；不可用项目仍可归档，重命名需要项目库可写。

## 本机协议与接口

每次启动由 Electron 分别生成服务令牌和实例 UUID，经标准输入传递；标准输入保持打开，同时承担父进程存活检测。服务只绑定 `127.0.0.1`，操作系统选择端口。服务输出 ready 消息后，Electron 再请求探活，核对 `service`、`instanceId`、`protocolVersion=1` 和 `ready=true`。令牌只在主进程和服务中使用，通过 HTTP Authorization 传递，不下发到 renderer，不写入 URL 或命令行。

所有接口需要当前服务令牌。错误为 `{code,message}`。输入、认证、不存在、冲突及不可用分别使用 HTTP 400、401/403、404、409、503。项目类型为 `{id,name,root,archived,availability}`，目录状态为 `available | missing | unreadable | invalid`。

| 接口 | 所属 | 行为 |
| --- | --- | --- |
| `GET /health/ready` | Java、Python | 返回服务身份、协议版本和就绪状态 |
| `POST /internal/shutdown` | Java、Python | 请求关闭当前服务 |
| `GET /api/v1/projects` | Java | 返回所有登记项目，包含归档及可用性 |
| `POST /api/v1/projects` | Java | `{name,directory?,clientRequestId}`；新建 201，重复结果 200 |
| `GET /api/v1/projects/{id}` | Java | 获取单个登记项目 |
| `PATCH /api/v1/projects/{id}` | Java | `{name?,archived?}`，至少一个字段 |

名称去除首尾空白后为 1—80 个字符；`clientRequestId` 为 UUID。相同请求标识和相同规范化参数返回原项目；参数不一致返回 `REQUEST_CONFLICT`。重复目录或已有项目数据返回 `DIRECTORY_CONFLICT`。

前端使用白名单桥接的 `projects.list/get/create/patch/openFolder`、`getRuntime`、`onRuntimeStatus`、`retryService` 和 `chooseDirectory`。Java 页面不调用旧 `snapshot`。服务启动上限 60 秒，Java 就绪即可管理项目；Python 独立失败、独立重试。完全退出最多等待 10 秒后只终止本次启动且仍存活的进程；父进程异常退出时服务通过管道关闭主动退出。Windows 虚拟环境可能有 Python 启动器与工作进程两层；启动器意外退出时主进程也关闭管道，促使工作进程退出。

后续学习任务约定：`submitAnswer` 先由 Java 保存回答并返回 `messageId/runId`，`getRun` 查询任务，`cancelRun` 请求取消。事件携带 `projectId/runId/sequence`；模型文字只作预览，最终业务完成事件在 Java 成功提交后发出。本批没有实现这些学习接口或 SSE。异常后的手动重试复用已保存回答，生效后的取消拒绝迟到结果。
